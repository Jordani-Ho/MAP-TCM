# ADR-003：分布式双域共同大脑

- Status: Accepted Architecture Baseline / Not Implemented
- Date: 2026-08-03
- Governing charter: MAP-008 v0.2

## Context

MAP 的知识系统需要同时满足四个看似矛盾的目标：经典与原始事实不能被覆盖；病症、干预和结局知识必须持续学习；每个医生与患者需要个性化智能体；整个社区又需要一个可共享的人类健康总知识体。把所有资料复制到中央数据库既破坏个人数据主权，也无法表达不同节点的个性、授权和责任边界。

Founder 将知识库定义为辨证施治的共同大脑。为避免把“认知主体”误解成“自主执业主体”，架构必须同时固定知识系统、患者和医生三类主体职责。

## Decision

MAP 采用双域知识模型和联邦式节点拓扑。

### 1. 不可覆盖基础域

包含：

- 固定版本的经典原文、扫描件、转录、出处和内容哈希；
- 患者基础信息与原始健康事实事件；
- 同意、授权、来源、签署和纠正事件。

原对象不执行覆盖式更新。录入错误通过 `correction_event` 指向被纠正对象；患者状态变化通过新事实事件表示；面向使用者的“当前信息”是可重建的投影，不是对历史记录的改写。访问权限与内容不可覆盖是两条独立规则：不可覆盖不意味着公开。

### 2. 持续演进学习域

包含：

- 病症观察、证候候选、干预暴露、结局、不良事件和反例；
- 医生的授权经验、评审、修改理由和适用边界；
- 医生成效与特点的版本化统计；
- 患者个人健康趋势和群体模式；
- 主张、反主张、共识快照、争议、废止和撤回依赖。

该域只追加事件和统计版本。新证据可以改变当前结论，但不能删除旧证据、失败案例或历史统计快照。

### 3. 联邦式节点

- `personal_health_agent_node`：保存个人纵向事实、偏好、目标和趋势；本人是数据与同意主体。
- `doctor_agent_node`：保存医生个性化工作流、私有经验和授权知识；不能冒充医生签署。
- `care_institution_node`：保存机构受控记录、身份、资质和安全流程。
- `commons_node`：保存获准共享的来源索引、知识对象、反例、评审和聚合证据，不默认保存各节点的原始病历。

节点交换统一的知识信封，至少携带：稳定对象标识、对象类型、来源节点、作者/责任主体、时间、版本、内容哈希、证据标签、授权或许可引用、访问级别、适用范围、撤回规则和审计证明。

### 4. 主体与决定权

- 知识系统是认知与协作主体：组织记忆、检索、比较、统计、提示冲突和生成草稿。
- 患者是数据、同意与权利主体：智能体不得替其同意或虚构体验。
- 现实医生是临床决定与责任主体：只有获授权医生能确认辨证、施治、沟通和签署。

社区总知识、医生节点或个人节点的模型输出都不能自动升级为正式诊疗决定。

## 成效统计治理

任何医生“成功率”或特点分析必须同时记录：

1. 结局定义及由谁确认；
2. 病症、证候和适用人群；
3. 样本量、纳入/排除规则与病例组合；
4. 随访窗口、失访和缺失率；
5. 实际干预暴露、合并治疗与依从性；
6. 不良事件、加重、转诊与失败案例；
7. 统计方法、置信范围、数据版本和生成时间；
8. 授权范围、隐私阈值与潜在利益冲突。

缺少这些条件时不得显示单一成功率。此类统计默认用于医生自我改进、患者共同决策研究和质量治理，不用于公开排行榜、疗效承诺、自动分诊或惩罚性绩效评价。

## 患者趋势治理

个人趋势优先与本人历史基线比较，并分离 `patient_fact`、`doctor_observation`、`doctor_judgment`、`external_evidence` 与 `ai_draft`。趋势模型必须显示数据覆盖区间、缺失、来源和不确定性；不得从相关变化自动推出病因、证候或疗效。

## Federation rules

1. 原始可识别病历默认留在授权节点；跨节点共享需独立目的和最小权限。
2. 优先交换去标识化知识对象、聚合统计或验证结果，而非明细数据。
3. 每次发布、同步、拒绝、撤回和重算都写审计事件。
4. 节点可以拒绝不符合本地法律、同意或安全策略的知识对象。
5. 撤回不删除历史审计；依赖被撤回贡献的当前聚合必须按规则重算或标记不可再用。
6. 节点断开后仍能验证已接收对象的来源、版本与完整性。

## Consequences

该决策给出了长期知识架构，但 Alpha 尚未实现真实联邦、隐私保护聚合、医生统计或个人趋势模型。当前 MAP-KNOW-002 只验证单节点、合成数据的贡献与共识状态机。下一阶段 MAP-KNOW-003 应先用多个合成节点验证信封、同步、冲突、撤回依赖和统计门禁，再讨论真实数据或跨机构试点。
