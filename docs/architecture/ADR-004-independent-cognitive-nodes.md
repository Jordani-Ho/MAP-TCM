# ADR-004：独立认知节点与点对点知识交换

- Status: Accepted Architecture Baseline / Documentation First
- Date: 2026-08-21
- Governing charter: MAP-008 v0.3
- Supersedes: ADR-003 的 `commons_node` 与人类健康总知识体拓扑

## Context

ADR-003 已经把医生、患者和机构知识分布到不同节点，但仍假定存在一个接收共享主张、评审和聚合证据的 `commons_node`。Founder 进一步明确：每一个知识库都应当是独立智能体的基础设施，社区不应拥有共同大脑或总知识库。不同节点共同遵循中医经典理论根系，但保留各自理解角度、深度、经验和演化路径。

如果继续保留中央公共知识节点，即使它不保存原始病历，也会逐步形成事实上的统一解释权、汇聚激励和平台控制点，与去中心化目标冲突。

## Decision

### 1. 每个智能体拥有独立知识库

- 每个 `doctor_agent_node` 只代表绑定医生的经典理解、辨证框架、经验和修改历史；
- 每个 `personal_health_agent_node` 只代表其所有者的身份、健康事实、学习、行动和派生知识；
- 节点有独立标识、所有者、密钥、存储、模型策略、版本历史和授权策略；
- 不存在逻辑或物理上的全局知识所有者。

### 2. 删除中央知识拓扑

长期架构不再包含：

- `commons_node`；
- 人类健康总知识体；
- 全局唯一 `consensus_snapshot`；
- 默认把节点经验、病例模式或观点汇入中央仓库的贡献管道；
- 由平台宣布全社区唯一正确解释的晋升状态机。

已有 `knowledge_contributions`、`knowledge_claims`、`knowledge_reviews` 和 `consensus_snapshots` 合成实现暂不删除。它们进入迁移评估：可复用部分重命名为节点内主张、反主张、审查和本地快照；无法满足节点归属与隔离的部分废止。迁移前不得将这些表接入真实数据或对外宣称为社区共识。

### 3. 共同经典根系采用可复制来源目录

MAP 可以提供作品标识、版本、章节、哈希、权利状态和引用格式协议。目录可被多个节点复制、验证或镜像，但不保存统一解释，不构成知识大脑，也不授予平台对现代作品或节点解释的权利。

### 4. 节点间使用知识信封

节点之间只按明确目的点对点发送 `knowledge_envelope`。信封至少携带：

- 对象标识、类型、来源节点和作者；
- 版本、创建时间、内容哈希和引用来源；
- 内容类别与临床权限；
- 证据、反例、适用范围和不确定性；
- 接收者、用途、访问级别、保留期限及再转发/派生权限；
- 更正、撤回、过期和审计规则。

接收方可以拒绝、临时使用、保存为外部观点或形成带来源的新本地理解。接收不等于认可；本地认可不等于跨节点共识。

### 5. 患者与医生的临时会诊保持独立

医生智能体在有效照护任务中可以临时读取当前患者节点的获准资料，但不得复制患者原文到医生永久知识库。会话关闭、关系终止、授权撤回、目的完成或期限届满后立即失效。责任快照只保存必要的来源标识、版本、哈希和正式记录引用。

### 6. 共同治理协议，不治理统一思想

社区可以共同维护来源、交换、身份、授权、审计、临床安全和互操作协议。社区不能强迫节点上交私域、接受某一解释，或通过多数投票把观点升级为全体真理。

## Invariants

1. 每个知识对象必须归属于一个明确节点或作为临时外部信封存在；
2. 任一持久化查询都不能在缺少节点和主体范围时遍历所有个体知识；
3. 不存在能够返回“全社区当前真理”的接口；
4. 经典来源与节点解释使用不同对象类型；
5. 外部信封不得静默改写为本节点原创内容；
6. 患者原始资料不得通过知识信封进入医生永久知识库；
7. AI 草稿不能成为医生签署或节点所有者确认；
8. 节点断开后仍可验证已接收信封的来源、版本和完整性；
9. 撤回停止未来非必要使用，但不抹除依法或安全所需的最小审计；
10. 多节点重复观点不自动产生临床权威。

## Consequences

### Positive

- 去除中央知识权威和数据汇聚单点；
- 更忠实表达不同医师的师承、框架和持续成长；
- 患者节点能够保持完整个人健康私域和自主学习路径；
- 模型、存储和实现可以多样化而仍保持协议互操作；
- 节点协作可以发生，但不会抹平分歧或强迫形成统一答案。

### Cost

- 跨节点搜索、发现、去重和研究统计更复杂；
- 不再依赖中央共识解决冲突，使用者必须看见来源和分歧；
- 需要节点密钥、信封验证、过期/撤回、离线同步和本地派生治理；
- 原 MAP-KNOW-002/003 合同和数据表需要迁移，而不是直接沿用。

## Migration

1. 文档和产品术语停止使用“共同大脑”“人类健康总知识体”和“中央共识”；
2. 将现有知识状态机限定为单一合成节点内的本地主张生命周期；
3. 为所有知识对象增加明确 `node_id`、所有者和作用域；
4. 以 `knowledge_envelope` 替代向公共节点贡献的工作流；
5. 用两个合成医生节点和两个合成患者节点验证拒绝、接收、派生、过期和撤回；
6. 迁移完成前保持真实数据、全局检索和跨节点自动聚合关闭。
