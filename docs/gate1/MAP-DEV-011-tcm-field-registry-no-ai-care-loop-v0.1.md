# MAP-DEV-011：TCM 候选字段注册表与无 AI 照护闭环 0.1

状态：`Engineering Pre-review Complete / Synthetic Only`

## 结论

TCM-CLIN-001 0.1.0 已作为服务端版本化注册表接入，但仍严格标记为 `candidate_for_doctor_review`、`clinical_approval=false`。这项实现只证明字段合同可以被机器校验和运行，不代表合作医生已经确认字段，也不构成临床标准。

在完全关闭 AI 的条件下，合成数据已经跑通：

`初诊记录 → 真人医生审核/签署 → 版本化干预计划 → 患者执行事件 → 患者反馈 → 复诊引用上次签署记录 → 医生前后比较 → 复诊签署`

## 已实现

### 1. 版本化候选字段注册表

- 按 `contract_id + schema_version + contract_hash` 登记合同；
- 同一版本内容变化时拒绝覆盖，必须发布新版本；
- 47 项（以合同实际数量为准）字段定义逐项登记适用就诊类型、值类型、必填级别、未知状态、证据标签、来源角色、审核责任和敏感级别；
- 注册表版本、字段定义和字段连接均由 SQLite 触发器禁止更新或删除；
- 服务器提供候选完整度报告，但该报告明确 `candidate_gate_only=true`，不能被解释为临床批准。

### 2. 正式字段写入边界

- 正式字段只接受 `patient / doctor / file / system` 来源；
- `ai` 来源被拒绝，AI 内容只能进入原有独立 `ai_draft` 区；
- 医生判断字段只能由 `verified_doctor` 以医生来源写入，并明确为医生已审核；
- 缺失信息必须使用 `unknown / not_collected / not_applicable / declined`，不能被默认为正常；
- HTTP 结构化字段写入继续经过服务端会话、关系、同意、目的/范围和对象状态授权，并与允许证据、业务写入和最小 Outbox 同事务提交。

### 3. 无 AI 合成照护闭环

- 干预计划独立版本化并引用已签署临床记录；
- 执行事件和患者反馈事件追加保存，数据库禁止原位修改或删除；
- 复诊必须连接上次已签署记录和所执行的计划版本；
- 系统可确定性地把执行与反馈投影为复诊的变化、依从/暴露、结果体验、不良事件和未采集的新诊断/用药字段；
- 医生前后比较必须显式引用上次签署记录，随后仍由真人医生完成审核和签署；
- 全流程不调用模型，不依赖 OpenAI API 或任何国内模型。

## 数据边界

本实现只使用 `SYN-*` 合成主体和合成内容。未开放真实身份、病历、照片、音视频、处方或医生临床行为。Outbox 仍只包含对象、状态、版本和责任快照引用，不复制患者叙述或辨证原文。
