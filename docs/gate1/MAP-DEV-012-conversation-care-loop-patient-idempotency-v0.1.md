# MAP-DEV-012：对话式照护闭环与患者自写幂等 0.1

状态：`Engineering Pre-review Complete / Synthetic Only`

## 结论

Gate 1 P0-6 已把 MAP-DEV-011 的无 AI 照护闭环接入对话式客户端，并为患者本人提交执行记录和反馈补齐服务端会话授权、幂等与原子写入边界。当前实现仍只处理 `SYN-*` 合成主体，不开放真实患者、真实医生或真实多模态资料。

客户端第一心智模型从“功能菜单”调整为“正在和谁交流”。患者进入“患者健康辅导员（AI）”，医生进入“医师智能体徒弟（AI）”；事实确认、医生行动、患者反馈、复诊差异和医生审核作为对话内结构化卡片出现。聊天文字仍不等于病历，AI 仍不能签署。

## 已实现

### 1. 患者本人自写授权

- 新增 `care_event.write` 能力，只允许服务端会话中的患者写入本人执行与反馈事件；
- 授权目的固定为 `self_health_tracking`，客户端提交的角色或主体字符串不构成授权；
- 医生、管理员或其他患者不能代替患者创建本人执行/反馈事件；
- 允许决定产生不可变授权证据，拒绝请求只保留拒绝审计。

### 2. 幂等与原子写入

- 每次请求必须提交 8–128 字符的 `Idempotency-Key`；
- 幂等范围由患者安全主体、操作类型和幂等键共同确定；
- 同一键与同一请求内容重复提交时返回首次最小响应，不重复创建事件；
- 同一键搭配不同内容时明确拒绝为冲突，不静默覆盖；
- 允许证据、执行/反馈事件、证据连接、最小 Outbox 和幂等记录在同一 SQLite 事务提交；任何一步失败全部回滚。

### 3. 对话内照护卡片

- 健康事实确认卡：显示来源锚点，并允许确认、修改或拒绝；
- 医生确认行动卡：显示待执行、执行中和已完成状态；
- 患者反馈卡：记录主观变化及不良反应标记；
- 复诊差异卡：确定性引用上次签署记录、实际执行、患者体验和不良事件；
- 医生审核卡：显示来源、候选字段缺口和前后比较，签署门禁继续关闭；
- 文字、语音、照片、视频和文件入口当前只作合成界面演示，不读取设备、不上传、不保存。

### 4. 页面与分享入口

- 页面标题更新为“MAP 治未病 AI 社区”；
- 分享预览图呈现“患者健康辅导员 × 医师智能体徒弟”与“观·辨·行·验·传”循环；
- 国内正式入口仍不能依赖 `chatgpt.site`，现有站点只作为内部合成预览；患者合伙人继续使用离线包参与评审。

## 安全与数据边界

Outbox 只包含对象编号、状态、版本和哈希，不包含患者叙述、反馈原文或多媒体内容。幂等响应同样保持最小化。患者自写事件不能修改或删除，签署病历继续不可变；任何 AI 内容只能作为独立草稿供真人医生审核。
