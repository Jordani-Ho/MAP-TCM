# MAP-DEV-007｜服务端会话授权临床 API 0.1

> 2026-08-13 后续状态：本文件记录的授权—临床写入竞态窗口已由 MAP-DEV-010 在合成 SQLite 运行时通过授权证据、业务写入和 Outbox 同一事务解决；生产数据库并发、幂等和投递器仍未完成。

- 状态：Synthetic Implementation Complete / Human Review Pending
- 日期：2026-08-13
- 范围：Gate 1 P0-1
- 数据边界：仅允许 `SYN-` 合成患者与合成身份；不批准真实临床使用

## 1. 结果

临床 HTTP 写接口不再信任请求正文中的 `actor_id` 或 `actor_role`。创建就诊、追加观察、形成医生判断、审核、签署和撤回均通过服务端会话解析主体，并同时检查医生资质、当前患者、活跃照护关系、目的、资料范围、记录状态及签署前近期再次验证。

客户端仍可提交 `actor_role` 作为安全测试输入，但该值只进入授权审计的 `client_role_claim`，并明确记录 `client_role_authoritative=false`，不能提升权限。临床记录中的作者和签署医生取自服务端会话主体。

## 2. 授权路径

```text
X-MAP-Session-ID
  → 服务端解析会话与主体
  → 校验账户、核验状态和医生资质
  → 将合成患者记录映射到患者安全主体
  → 校验活跃照护关系
  → 校验 purpose 与 data_categories 是否在有效授权范围内
  → 审核/撤回要求 clinical_record.write
  → 签署要求 clinical_record.sign + doctor_reviewed 状态 + 近期再次验证
  → 使用服务端 subject_id 写入临床记录与审计
```

## 3. 合成工作台兼容

本地工作台通过 `/api/v1/synthetic/context` 获取短时合成医生会话。该入口只允许本机地址，不能在远程请求中获取会话；公开的产品原型不调用此 API，也不连接真实临床数据。

## 4. 已验证的拒绝场景

- 缺少服务端会话，即使客户端自称医生也拒绝；
- 管理员或其他角色即使伪造医生声明也拒绝；
- 医生写入没有照护关系的另一患者时拒绝；
- 会话撤销或过期后拒绝；
- 患者撤回系统授权后，新临床写入立即拒绝；
- 签署仍要求医生判断、正确记录状态和近期再次验证；
- 客户端伪造 `actor_id` 不会成为医生判断的作者。

## 5. 尚未解除的门禁

0.1 中授权决策和临床写入仍是相邻但独立的 SQLite 事务。进入生产前，必须在 P0-4 审计强化中形成统一应用事务、授权证据快照与 Outbox，消除授权通过后到写入前发生撤回的竞态窗口。

此外仍未完成：生产身份提供者、不可变 ClinicalRecordVersion、字段级来源锚点、加密 Vault/KMS、备份恢复、保留/删除政策、真实医生资质核验和法律隐私批准。因此本实现不能承载真实患者资料，不能视为真实临床签署系统。

## 6. 真人技术合伙人审查点

1. 是否批准 HTTP 临床写入只接受服务端会话的边界；
2. 是否批准合成患者记录与安全主体在 0.1 中按合成显示码映射；
3. 是否同意 P0-2 先实现不可变临床版本，P0-4 再把授权、写入与 Outbox 收敛为统一事务；
4. 是否要求在 P0-2 前先引入显式 PatientRecord–Subject 关联键。
